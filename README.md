# Настройка нового VPS на Ubuntu 24.04

Инструкция и скрипт рассчитаны на сценарий: **веб-сервер**, вход пока **по паролю**, открытые порты **22 (SSH), 80, 443**.

## 1. Первый вход и подготовка

```bash
ssh root@ВАШ_IP
```

Загрузите скрипт на сервер (например, через `scp` со своего компьютера):

```bash
scp setup-vps.sh root@ВАШ_IP:/root/
```

или скопируйте содержимое файла напрямую на сервере через `nano setup-vps.sh`.

## 2. Проверьте настройки в начале скрипта

Откройте `setup-vps.sh` и при желании поменяйте:

- `NEW_USER` — имя нового администратора (по умолчанию `andy`);
- `SSH_PORT` — можно оставить 22 или сменить на нестандартный (рекомендуется, но не обязательно);
- `ALLOWED_TCP_PORTS` — какие порты открыть кроме SSH (по умолчанию 80 и 443);
- `TIMEZONE` — часовой пояс сервера.

## 3. Запустите скрипт

```bash
chmod +x setup-vps.sh
sudo ./setup-vps.sh
```

Скрипт выполнит:

1. Полное обновление системы (`apt update/upgrade/dist-upgrade`, очистка).
2. Установку базовых утилит: `ufw`, `fail2ban`, `unattended-upgrades`, `htop`, `vim` и др.
3. Установку часового пояса и синхронизацию времени.
4. Создание нового sudo-пользователя (вместо работы под root), с копированием SSH-ключей root, если они уже были добавлены хостером.
5. Настройку firewall UFW: закрыты все порты кроме SSH, 80 и 443.
6. Базовое ужесточение SSH: запрет входа под root, ограничение попыток авторизации.
7. Настройку fail2ban для бана IP при переборе паролей по SSH.
8. Автоматические обновления безопасности (unattended-upgrades).
9. Базовые сетевые настройки безопасности (sysctl) и swap-файл 2 ГБ.

После выполнения **не закрывайте текущую SSH-сессию** — откройте новое окно терминала и проверьте вход новым пользователем:

```bash
ssh deploy@ВАШ_IP
```

Убедитесь, что вход работает и `sudo` доступен (`sudo whoami` должен вернуть `root`), только после этого закрывайте старую сессию.

## 4. Переход на SSH-ключи (сделайте как можно скорее)

Вы выбрали вход по паролю — это работает, но заметно менее безопасно, особенно при переборе (brute-force). Рекомендация: как можно быстрее перейти на ключи.

**На своём компьютере**, если ключа ещё нет:

```bash
ssh-keygen -t ed25519 -C "vps-key"
```

Скопируйте публичный ключ на сервер:

```bash
ssh-copy-id -i ~/.ssh/id_ed25519.pub deploy@ВАШ_IP
```

Проверьте, что вход по ключу работает:

```bash
ssh -i ~/.ssh/id_ed25519 deploy@ВАШ_IP
```

Только после успешной проверки — отключите пароли на сервере:

```bash
sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo sshd -t && sudo systemctl restart ssh
```

## 5. Дальнейшие рекомендации

- **Веб-сервер**: скрипт не устанавливает nginx/apache — установите отдельно под ваш стек, например:
  ```bash
  sudo apt install -y nginx
  sudo ufw status   # 80/443 уже открыты
  ```
- **SSL**: используйте Let's Encrypt / certbot для бесплатных сертификатов.
- **Резервные копии**: настройте регулярный бэкап конфигов и данных (снапшоты у хостера или `rsync`/`restic` на внешнее хранилище).
- **Мониторинг**: рассмотрите `htop`/`btop` для базового мониторинга, либо внешние сервисы (UptimeRobot, Netdata) для алертов о падении сервиса.
- **Логи fail2ban**: посмотреть забаненные IP — `sudo fail2ban-client status sshd`.
- **Обновления**: `unattended-upgrades` тянет только security-патчи автоматически; полный `apt upgrade` всё равно делайте руками время от времени.
- **Нестандартный SSH-порт**: если решите сменить порт с 22 на другой — не забудьте открыть новый порт в UFW *до* перезапуска SSH, иначе рискуете потерять доступ.
- **UFW-логи**: если нужно понять, что блокируется — `sudo ufw status verbose` и `/var/log/ufw.log`.

## 6. Что делать, если что-то пошло не так

- Резервная копия конфига SSH сохраняется скриптом автоматически: `/etc/ssh/sshd_config.bak.<timestamp>`.
- Если потеряли доступ по SSH — используйте веб-консоль (VNC/serial console) вашего хостера, доступную даже без сети.
