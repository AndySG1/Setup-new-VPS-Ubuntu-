# Настройка нового VPS на Ubuntu 24.04

Скрипт `setup-vps.sh` за один запуск обновляет систему, создаёт администратора, настраивает firewall и SSH, включает fail2ban и автообновления, и по желанию ставит дополнительное ПО. Скрипт **идемпотентен** — его можно безопасно запускать повторно, уже выполненные шаги пропускаются.

## 1. Что настраивает скрипт

| # | Шаг | Описание |
|---|-----|----------|
| 1 | Обновление системы | `apt update/upgrade/dist-upgrade`, очистка |
| 2 | Базовые утилиты | `ufw`, `fail2ban`, `unattended-upgrades`, `htop`, `vim` и др. |
| 3 | Часовой пояс | установка и синхронизация времени |
| 4 | Пользователь | создаёт sudo-пользователя вместо работы под root |
| 5 | SSH-ключ | копирует ключи root (если были) + добавляет введённый вами |
| 6 | Firewall (UFW) | закрыто всё, кроме SSH-порта, 80 и 443 |
| 7 | SSH hardening | запрет root-логина, лимит попыток входа, пароль вкл/выкл по вашему выбору |
| 8 | fail2ban | бан IP при переборе паролей по SSH |
| 9 | Автообновления | `unattended-upgrades` для security-патчей |
| 10 | sysctl + swap | базовое сетевое ужесточение, swap-файл 2 ГБ |
| 11 | Доп. ПО | установка выбранных пакетов из меню |

Целевой сценарий по умолчанию: **веб-сервер**, открытые порты — SSH (по умолчанию 22), 80, 443.

## 2. Подготовка: загрузка скрипта на сервер

Подключитесь к серверу:

```bash
ssh root@ВАШ_IP
```

Скрипт лежит в репозитории на GitHub:
https://github.com/AndySG1/Setup-new-VPS-Ubuntu-/blob/main/setup-vps.sh

**Вариант A — `git clone` (репозиторий публичный):**

```bash
apt update && apt install -y git   # git может отсутствовать на свежем образе
git clone https://github.com/AndySG1/Setup-new-VPS-Ubuntu-.git
cd Setup-new-VPS-Ubuntu-
```

**Вариант B — скачать только файл скрипта через `curl`:**

```bash
curl -O https://raw.githubusercontent.com/AndySG1/Setup-new-VPS-Ubuntu-/main/setup-vps.sh
```

**Вариант C — скопировать со своего компьютера** (если репозиторий приватный и `git clone`/`curl` не работают без авторизации):

```bash
scp setup-vps.sh root@ВАШ_IP:/root/
```

Сделайте скрипт исполняемым:

```bash
chmod +x setup-vps.sh
```

## 3. Параметры запуска

Все параметры можно задать заранее — тогда соответствующий интерактивный вопрос пропускается.

| Параметр | Флаг | Переменная окружения | По умолчанию |
|---|---|---|---|
| Имя администратора | `-u`, `--user` | `NEW_USER` | `deploy` |
| Порт SSH | `-p`, `--port` | `SSH_PORT` | `22` |
| Использовать SSH-ключ | — | `USE_SSH_KEY=yes\|no` | `no` |
| Сам публичный ключ | — | `SSH_PUB_KEY="ssh-ed25519 ..."` | — |
| Отключить пароль | — | `DISABLE_PASSWORD_AUTH=yes\|no` | `no` |
| Доп. пакеты (номера через пробел) | — | `SELECTED_PACKAGES="1 3 6"` | — |
| Пропустить все вопросы | `-y`, `--yes` | — | — |

Параметры `ALLOWED_TCP_PORTS` и `TIMEZONE` пока меняются только внутри самого файла скрипта.

**Пример полностью неинтерактивного запуска:**

```bash
sudo USE_SSH_KEY=yes SSH_PUB_KEY="ssh-ed25519 AAAA... you@host" \
     DISABLE_PASSWORD_AUTH=yes SELECTED_PACKAGES="1 2 7" \
     ./setup-vps.sh -u alex -p 2222 -y
```

## 4. Запуск и интерактивные вопросы

```bash
sudo ./setup-vps.sh
```

Если не всё задано флагами/переменными, скрипт спросит по порядку:

1. **Имя пользователя и SSH-порт** — Enter оставляет значение по умолчанию.
2. **Настроить вход по SSH-ключу?** (`Y/n`) — при согласии попросит вставить публичный ключ одной строкой (например, содержимое `~/.ssh/id_ed25519.pub`). Ключ, уже добавленный хостером в root, копируется новому пользователю в любом случае.
3. **Отключить вход по паролю?** (`y/N`) — доступно, только если ключ реально найден (свой или от root); иначе скрипт сам оставит пароль включённым и предупредит об этом.
4. **Список дополнительного ПО** — пронумерованное меню, номера вводятся через пробел:

   ```
   1) Nginx              6) Node.js (LTS)
   2) Docker + Compose   7) Certbot (Let's Encrypt)
   3) MySQL Server       8) PHP-FPM
   4) PostgreSQL         9) Git
   5) Redis

   Номера нужных пакетов через пробел (например: 1 3 6): 1 7 9
   ```

   Enter без ввода — ничего дополнительного не ставится.

После этого скрипт выполняет все 11 шагов из раздела 1 без дальнейших вопросов.

## 5. Проверка после запуска

**Не закрывайте текущую SSH-сессию.** Откройте новое окно терминала и проверьте вход новым пользователем и портом:

```bash
ssh -p ВАШ_SSH_ПОРТ deploy@ВАШ_IP
sudo whoami   # должно вернуть root
```

Только после успешной проверки закрывайте старую сессию.

## 6. Управление SSH-доступом

### Если пароль остался включён — переход на ключи

Рекомендуется сделать как можно скорее, если вы не настроили ключ во время запуска скрипта.

На своём компьютере, если ключа ещё нет:

```bash
ssh-keygen -t ed25519 -C "vps-key"
```

Скопируйте ключ на сервер и проверьте вход:

```bash
ssh-copy-id -p ВАШ_SSH_ПОРТ -i ~/.ssh/id_ed25519.pub deploy@ВАШ_IP
ssh -p ВАШ_SSH_ПОРТ -i ~/.ssh/id_ed25519 deploy@ВАШ_IP
```

Только после успешной проверки отключите пароль на сервере:

```bash
sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo sshd -t && sudo systemctl restart ssh
```

### Возврат входа под root

Скрипт отключает `PermitRootLogin` из соображений безопасности. Если нужно вернуть:

```bash
sudo sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin yes/' /etc/ssh/sshd_config
sudo sshd -t && sudo systemctl restart ssh
```

Или откатить весь конфиг из автоматического бэкапа скрипта:

```bash
ls -la /etc/ssh/sshd_config.bak.*
sudo cp /etc/ssh/sshd_config.bak.<timestamp> /etc/ssh/sshd_config
sudo sshd -t && sudo systemctl restart ssh
```
(Это вернёт **все** настройки SSH к состоянию до скрипта, а не только root-логин.)

> Если при этом `PasswordAuthentication` выключен — вход под root по паролю всё равно не заработает, понадобится SSH-ключ именно в `/root/.ssh/authorized_keys`.

## 7. Повторный запуск и доустановка ПО

Скрипт можно запускать повторно в любой момент — например, чтобы добавить ещё один пакет или сменить порт. Каждый шаг сам проверяет, выполнен ли он уже (пользователь существует, пакет установлен, ключ добавлен, swap создан и т. д.) и пропускает повторную работу:

```bash
sudo ./setup-vps.sh
```

## 8. Рекомендации

- **Веб-сервер**: если не выбрали Nginx в меню — установите отдельно:
  ```bash
  sudo apt install -y nginx
  sudo ufw status   # 80/443 уже открыты
  ```
- **SSL** — используйте Let's Encrypt / certbot (пункт 7 в меню доп. ПО) для бесплатных сертификатов.
- **Резервные копии** — настройте регулярный бэкап конфигов и данных: снапшоты у хостера или `rsync`/`restic` на внешнее хранилище.
- **Мониторинг** — `htop`/`btop` для базового контроля, либо внешние сервисы (UptimeRobot, Netdata) для алертов о падении.
- **fail2ban** — посмотреть забаненные IP: `sudo fail2ban-client status sshd`.
- **Обновления** — `unattended-upgrades` тянет только security-патчи автоматически; полный `apt upgrade` всё равно делайте руками время от времени.
- **Смена SSH-порта** — открывайте новый порт в UFW *до* перезапуска SSH, иначе можно потерять доступ.
- **UFW-логи** — `sudo ufw status verbose` и `/var/log/ufw.log`.

---

## 9. Решение проблем

- Резервная копия `sshd_config` сохраняется скриптом автоматически: `/etc/ssh/sshd_config.bak.<timestamp>`.
- Если потеряли доступ по SSH — используйте веб-консоль (VNC/serial console) вашего хостера, она доступна даже без сети.
- Если после смены порта не подключается снаружи — проверьте firewall/security group на стороне хостера (это отдельно от UFW на самом сервере).
