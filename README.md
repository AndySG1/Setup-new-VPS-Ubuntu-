# Настройка нового VPS на Ubuntu 24.04

Инструкция и скрипт рассчитаны на сценарий: **веб-сервер**, открытые порты **SSH (по умолчанию 22), 80, 443**. Вопрос про SSH-ключ, отключение пароля и выбор доп. ПО скрипт задаёт интерактивно при запуске.

Скрипт выполняет **все настройки за один запуск** и **идемпотентен**: его можно безопасно запускать повторно (например, чтобы доустановить ещё один пакет или поменять порт). Каждый шаг сначала проверяет, не выполнен ли он уже — пользователь существует, пакет установлен, ключ уже добавлен, swap уже создан и т.д. — и если да, просто выводит сообщение и переходит дальше, ничего не ломая.

## 1. Первый вход и подготовка

```bash
ssh root@ВАШ_IP
```

Скрипт лежит в репозитории на GitHub:
https://github.com/AndySG1/Setup-new-VPS-Ubuntu-/blob/main/setup-vps.sh

Самый простой способ — скачать его прямо на сервере через `git clone` или `curl`.

**Вариант A — git clone (если репозиторий публичный):**

```bash
apt update && apt install -y git   # git может отсутствовать на свежем образе
git clone https://github.com/AndySG1/Setup-new-VPS-Ubuntu-.git
cd Setup-new-VPS-Ubuntu-
```

**Вариант B — скачать только файл скрипта через curl:**

```bash
curl -O https://raw.githubusercontent.com/AndySG1/Setup-new-VPS-Ubuntu-/main/setup-vps.sh
```

Если репозиторий приватный, `git clone`/`curl` по HTTPS без авторизации не сработают — тогда проще скопировать скрипт со своего компьютера через `scp`:

```bash
scp setup-vps.sh root@ВАШ_IP:/root/
```

## 2. Задайте имя пользователя и SSH-порт

Имя нового администратора (`NEW_USER`, по умолчанию `deploy`) и порт SSH (`SSH_PORT`, по умолчанию `22`) теперь можно менять прямо при запуске — не обязательно редактировать сам файл. Есть три способа (в порядке приоритета):

**Способ A — флагами командной строки:**

```bash
sudo ./setup-vps.sh -u alex -p 2222
```

**Способ B — переменными окружения:**

```bash
sudo NEW_USER=alex SSH_PORT=2222 ./setup-vps.sh
```

**Способ C — интерактивно:** если ничего не передать флагами/переменными, скрипт сам спросит имя пользователя и порт при запуске (Enter — оставить значение по умолчанию). Чтобы пропустить вопросы и просто взять значения по умолчанию (или из флагов), добавьте `-y`/`--yes`.

Остальные параметры по-прежнему можно поменять только в самом файле:

- `ALLOWED_TCP_PORTS` — какие порты открыть кроме SSH (по умолчанию 80 и 443);
- `TIMEZONE` — часовой пояс сервера.

## 3. Запустите скрипт

```bash
chmod +x setup-vps.sh
sudo ./setup-vps.sh
```

Скрипт задаст по порядку несколько вопросов:

1. **Имя пользователя и SSH-порт** — Enter оставляет значение по умолчанию.
2. **Настроить вход по SSH-ключу?** (`Y/n`) — если да, попросит вставить публичный ключ одной строкой (например, содержимое `~/.ssh/id_ed25519.pub`). Если у вас уже есть ключ, добавленный хостером в root, можно просто нажать Enter — он будет скопирован новому пользователю автоматически в любом случае.
3. **Отключить вход по паролю?** (`y/N`) — доступно, только если ключ реально нашёлся (свой или скопированный от root); если ключа нет, скрипт сам оставит пароль включённым и предупредит об этом.
4. **Список дополнительного ПО** — выводится пронумерованный список, вводите нужные номера через пробел, например:
   ```
   1) Nginx
   2) Docker + Docker Compose
   3) MySQL Server
   4) PostgreSQL
   5) Redis
   6) Node.js (LTS)
   7) Certbot (Let's Encrypt)
   8) PHP-FPM
   9) Git

   Номера нужных пакетов через пробел (например: 1 3 6): 1 7 9
   ```
   Enter без ввода — ничего дополнительного не ставится.

Если хотите пропустить все вопросы и просто выполнить с настройками по умолчанию (или переданными флагами/переменными) — используйте флаг `-y`/`--yes`:

```bash
sudo ./setup-vps.sh -u alex -p 2222 -y
```

При этом SSH-ключ, отключение пароля и доп. пакеты можно задать заранее через переменные окружения:

```bash
sudo USE_SSH_KEY=yes SSH_PUB_KEY="ssh-ed25519 AAAA... you@host" \
     DISABLE_PASSWORD_AUTH=yes SELECTED_PACKAGES="1 2 7" \
     ./setup-vps.sh -u alex -p 2222 -y
```

После ответов на вопросы скрипт выполнит:

1. Полное обновление системы (`apt update/upgrade/dist-upgrade`, очистка).
2. Установку базовых утилит: `ufw`, `fail2ban`, `unattended-upgrades`, `htop`, `vim` и др.
3. Установку часового пояса и синхронизацию времени.
4. Создание нового sudo-пользователя (вместо работы под root).
5. Настройку SSH-ключа: копирует ключи root (если были) и добавляет введённый вами ключ.
6. Настройку firewall UFW: закрыты все порты кроме SSH, 80 и 443.
7. Базовое ужесточение SSH: запрет входа под root, ограничение попыток авторизации, вход по паролю включён/выключен согласно вашему ответу.
8. Настройку fail2ban для бана IP при переборе паролей по SSH.
9. Автоматические обновления безопасности (unattended-upgrades).
10. Базовые сетевые настройки безопасности (sysctl) и swap-файл 2 ГБ.
11. Установку выбранного дополнительного ПО.

После выполнения **не закрывайте текущую SSH-сессию** — откройте новое окно терминала и проверьте вход новым пользователем:

```bash
ssh deploy@ВАШ_IP
```

Убедитесь, что вход работает и `sudo` доступен (`sudo whoami` должен вернуть `root`), только после этого закрывайте старую сессию.

## 4. Если пароль остался включён — переход на SSH-ключи

Если во время выполнения скрипта вы ответили «нет» на вопрос про SSH-ключ (или ключ не нашёлся, и скрипт сам оставил пароль включённым) — рекомендуется перейти на ключи как можно скорее.

**На своём компьютере**, если ключа ещё нет:

```bash
ssh-keygen -t ed25519 -C "vps-key"
```

Скопируйте публичный ключ на сервер:

```bash
ssh-copy-id -p ВАШ_SSH_ПОРТ -i ~/.ssh/id_ed25519.pub deploy@ВАШ_IP
```

Проверьте, что вход по ключу работает:

```bash
ssh -p ВАШ_SSH_ПОРТ -i ~/.ssh/id_ed25519 deploy@ВАШ_IP
```

Только после успешной проверки — отключите пароли на сервере:

```bash
sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo sshd -t && sudo systemctl restart ssh
```

## 5. Дальнейшие рекомендации

- **Веб-сервер**: если не выбрали Nginx в списке доп. ПО при запуске скрипта — установите отдельно:
  ```bash
  sudo apt install -y nginx
  sudo ufw status   # 80/443 уже открыты
  ```
- **SSL**: используйте Let's Encrypt / certbot для бесплатных сертификатов.
- **Резервные копии**: настройте регулярный бэкап конфигов и данных (снапшоты у хостера или `rsync`/`restic` на внешнее хранилище).
- **Мониторинг**: рассмотрите `htop`/`btop` для базового мониторинга, либо внешние сервисы (UptimeRobot, Netdata) для алертов о падении сервиса.
- **Логи fail2ban**: посмотреть забаненные IP — `sudo fail2ban-client status sshd`.
- **Обновления**: `unattended-upgrades` тянет только security-патчи автоматически; полный `apt upgrade` всё равно делайте руками время от времени.
- **Нестандартный SSH-порт**: если решите сменить порт с 22 на другой — не забудьте открыть новый порт в UFW *до* перезапуска SSH, иначе рискуете потерять доступ.
- **UFW-логи**: если нужно понять, что блокируется — `sudo ufw status verbose` и `/var/log/ufw.log`.

## 6. Что делать, если что-то пошло не так

- Резервная копия конфига SSH сохраняется скриптом автоматически: `/etc/ssh/sshd_config.bak.<timestamp>`.
- Если потеряли доступ по SSH — используйте веб-консоль (VNC/serial console) вашего хостера, доступную даже без сети.
